## 확정한 사용·배치

- 상단 중앙 전체 목차, 페이지 양옆 중간 높이의 이전·다음 버튼, `?page=` 새로고침 복원을 사용합니다. 이미지는 같은 화면에서 확대합니다.
- `PDF로 저장`은 폰트와 전체 페이지 이미지가 준비된 후 브라우저 인쇄로 A4 가로 26쪽을 만듭니다. 현재 화면을 기업별 웹 URL로 열었다는 이유로 인쇄 내용까지 맞춤화되지 않습니다.
- 문제·배경 → 대안 비교·구현 → 검증 → 최종 결과 순서입니다. 3M의 경계 분리와 인증 정보 전달은 하나의 사례 안에서 연결되는 적용 단계입니다.
- **4·15쪽 배치를 유지합니다.** 소개·기간 → 가로 3단계 서비스 흐름 → 담당/효과 2열 → 하단 기술입니다.
- 1쪽 소개는 강제 줄바꿈 없는 한 문단입니다. 25쪽은 자료 링크 9개와 연락처, 26쪽은 중앙 감사 인사입니다.
- 테두리·주요 수치는 파란색 `#2563eb`, 연락처는 링크와 다른 청록색 `#0f766e`입니다. 증거 이미지의 원래 색·비율을 유지합니다.
- 효과·한계·검증 범위는 관련 내용과 묶습니다. 큰 중간 여백을 만들기 위해 하단 설명을 강제로 밀어내지 않습니다.

## 근거를 해석하는 기준

- 1,000명 목록 조회 평균은 `6.818 → 4.191 → 0.638초`입니다. Redis 단계에는 오류 732건/49,931건이 있으므로 오류 없는 검증으로 표현하지 않습니다.
- Scouter의 요청당 쿼리 `42 → 2회`, 캐시 적중 `0회`는 개별 요청 자료입니다. 평균 응답시간과 구분합니다.
- 투표의 HTTP 오류·중복 저장·DB와 Redis 대조는 각각 검증 대상을 명시합니다. 목록 조회의 오류와 섞지 않습니다.
- 3M의 0건은 User 모듈의 Auth 패키지 import 수입니다. 권한 응답은 로컬 H2 통합 테스트의 범위입니다.
- 46.9%는 2022년 도·소매업 소상공인의 경쟁 심화 응답 비율입니다. 이탈 방지는 개선 목적이며, 실제 이탈률이나 자동화 시간 절감률을 만들지 않습니다.
- Redis 키 유실 복구·조회 장애 시 DB 집계 응답은 [구현·테스트](https://github.com/dbp-jack/FeedShop_Backend_Refactoring/commit/61466a2) 근거입니다. DB와 Redis를 원자적으로 갱신하거나 운영 장애를 완전히 해결했다는 뜻은 아닙니다.
- AI 플래너는 사용자 설명·첨부 화면을 반영한 내용입니다. 챌린지 참여 상태는 제출 전 재확인합니다. `assets/planner-screen.png` 원본은 유지합니다.
- 회고는 경험에서 얻은 배움·판단 기준입니다. 개선 기능 목록이나 다음 할 일로 대체하지 않습니다.

## 누락 재발 방지 기준

이전 실패 원인은 요약하면서 핵심 근거·회고를 삭제하고, 비교 대상 및 사례 단위를 혼동한 것입니다. 이후 페이지 수를 줄이거나 구성을 바꿀 때 아래 항목을 먼저 대조합니다.

1. 목차, 사례 번호·이름, 프로젝트 회고, 자료, 마무리가 연결되는가.
2. 각 사례의 문제·대안 비교·직접 구현·결과·검증·한계를 찾을 수 있는가.
3. 평균 응답시간의 세 단계와 DB 조회·캐시 적중 수치를 모두 보존했는가.
4. 원인 화면, SQL 2회 화면, 캐시 SQL 0회 화면, 투표 부하·집계 자료, Auth/User 변경 전후 이미지, 인증 흐름도, 협업 이미지 3개가 남아 있는가.
5. 삭제·통합은 중복 설명에 한정하고, 필요한 근거는 본문 또는 명확한 연결로 보존했는가.
6. 페이지당 큰 제목 하나, 본문·이미지 잘림 없음, 이미지 확대·목차·새로고침 복원을 실제 브라우저에서 확인했는가.
7. 최종 결과 뒤에 중간 검증으로 되돌아가지 않는가. 표에 검증 목적·단위·측정 대상이 있고, `0건`이 무엇을 세는지 명시했는가.
8. 이미지 설명이 실제 화면에 보이는 근거와 일치하는가. 원본 화면으로 확인할 수 없는 내용은 별도 기록으로 연결했는가.
9. 결과 페이지에서는 완료한 조치와 확인된 효과를, 회고에서는 그 경험으로 얻은 배움·판단 기준을 전달했는가. 회고의 ‘얻은 점’을 기능·성과의 재나열이나 앞으로 할 일로 대체하지 않았는가. 사용자의 최신 교정을 우선한다.
10. 하단선·넘침만 확인하지 않고, 본문 중간에 큰 빈 공간이 몰리는지도 확인했는가. `PageBottom`은 관련 설명을 묶는 용도로 사용하며 `margin-top:auto`로 강제로 밀어내지 않는다. 효과·한계·검증 범위처럼 연결된 설명은 함께 두고, 주 자료의 비율을 조정한다. 가로로 긴 이미지는 칸 높이만 늘려 빈 공간을 채우지 않는다.
